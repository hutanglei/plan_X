# 通用批判式分析框架（Critical Analysis Framework）

对任何"榜单 / 排名 / 分析结论"进行结构化审视，输出"同意/部分同意/不同意"的明确立场，并给出可操作的修正建议。适用于：

- 行业研究：板块龙头榜、赛道标的筛选、FIC/创新管线评估
- 金融分析：估值测算、峰值销售预测、投资标的优选
- 产品设计：功能优先级排序、竞品对比、需求优先级评审
- 任何"基于多维标准对一组对象排序并下结论"的场景

## 核心立场原则

1. **先表态，再论证**：必须先给出"完全同意 / 部分同意 / 不同意"的明确立场，再展开论证，禁止含糊。
2. **区分事实与观点**：事实错误必须改；观点分歧可讨论但需说明依据。
3. **建设性优先**：指出问题的同时，必须给出可操作的修正方案，而非纯否定。
4. **诚实标注不确定性**：预测/测算类内容须标注来源、假设与置信度，不把"券商测算"当事实。

## 强制使用规则

**凡是用户提交一份"分析/榜单/排名/结论"并询问"你同意吗/有无遗漏/是否合理"时，必须按本框架逐项审视，禁止简单附和。**

## 五大审视维度（C-R-O-R-M）

### 维度1：事实核查（Fact-Check）

对分析中的**关键事实性陈述**逐一核实，重点盯：
- 数字：金额、占比、日期、市场规模--是否准确、单位是否统一
- 身份：交易对手、分子代号、公司归属、靶点/模态归属--是否张冠李戴
- 时点：事件是否已发生（须先用 `get-current-date` 校准真实日期，再判断"已兑现/未兑现"）
- 来源：测算数据是否有出处，是否把"预测"当"事实"

**输出格式**：逐条列出"原文陈述 → 核实真相 → 错误等级（重大/轻微/无误）"。

### 维度2：Scope 校验（Scope Validation）

检查分析范围与题目要求是否匹配：
- **地域/市场口径**：题目说"A股"却混入港股？题目说"全球"却只列国内？
- **时间口径**：是否用过期数据？是否把未来预期当现状？
- **对象口径**：按"公司"排还是按"管线/产品"排？是否重复计数（如同一公司占多席）？
- **可比性**：被比较的对象是否在同一维度（如已上市 vs III期 vs 早期，能否直接比峰值？）

**输出格式**：明确"题目要求范围 vs 实际覆盖范围 vs 偏差影响"。

### 维度3：遗漏补全（Omission Check）

主动检索是否有**应纳入而未纳入**的对象：
- 基于已有标的池/数据库，比对是否漏掉符合标准的成员
- 特别关注"近期新发生"的对象（新获批、新上市、新进入III期）--这些最易被旧榜单遗漏
- 检查是否有"细分赛道唯一代表"被忽略（如某靶点的国产首创）

**输出格式**：列出遗漏对象 + 遗漏原因（数据陈旧/口径偏差/认知盲区）+ 应补入的档位。

### 维度4：排序争议（Ranking Dispute）

对排序结果进行**逆向审视**：
- 是否有"档位偏高"：峰值测算是否乐观？竞争格局是否被忽视？
- 是否有"档位偏低"：受众是否被低估？是否一刀切扣分（如"小众靶点"忽略慢病属性）？
- 是否有"归类错误"：如把"长期服药慢病"归入"急性小众"档
- 边界案例：处于档位临界点的，上下浮动一档是否更合理？

**输出格式**：逐条列出"对象 → 现档位 → 建议档位 → 调整理由"。

### 维度5：方法论补强（Methodology Enhancement）

指出分析框架本身的不足，提出补强维度：
- **不确定性标注**：峰值/预测是否标注风险调整后值 vs 理论值？
- **兑现度权重**：已商业化放量 vs 刚获批 vs 早期临床，是否区分节奏？
- **竞争格局恶化**：FIC 是否有 followers 稀释稀缺性？
- **单位口径统一**：美元/人民币混用是否换算？档位边界是否明确？
- **权重透明度**：多维标准是否公开加权？还是黑箱？

**输出格式**：列出"方法论缺口 → 补强建议 → 对结论的影响"。

## 标准输出结构

对每份被审视的分析，按以下结构输出：

```
一、总体判断
   - 明确立场（完全同意/部分同意/不同意）
   - 一句话概括核心问题

二、重大事实错误（如有，必须改）
   - 逐条：原文 → 真相 → 错误等级

三、Scope 错配（如有）
   - 题目范围 vs 实际范围 vs 偏差影响

四、遗漏补全
   - 遗漏对象 + 应补入档位 + 遗漏原因

五、排序争议
   - 偏高/偏低/归类错误，逐条说明

六、方法论补强建议
   - 缺口 + 补强维度

七、小结
   - 一句话结论 + 是否需要重做
```

## 使用示例

### 示例1：金融分析（创新药FIC管线TOP榜）

用户提交一份"TOP15药企FIC管线峰值销售分级榜"，询问是否合理。

按本框架审视：
- **事实核查**：发现"荣昌维迪西妥授权艾伯维6.5亿首付"→实际是Seagen 2亿首付/26亿总对价，分子身份也错（RC48 HER2 ADC 被写成 RC148 PD-1/VEGF双抗）→重大错误
- **Scope校验**：题目说"沪深A股"，但康方/信达/科伦博泰/亚盛/先声/石药均为港股→约半数不在A股可投范围
- **遗漏补全**：智翔金泰GR1801（全球首个狂犬病双抗，2026-06刚获批）、益方KRAS、迈威Nectin-4 ADC等纯A股FIC被漏
- **排序争议**：迪哲舒沃替尼被放第四档偏低（exon20ins非超罕见，已中美双获批）；君实BTLA第二档偏乐观
- **方法论补强**：峰值均为券商宽口径测算须标注不确定性；缺"兑现度"维度；缺"竞争格局恶化"风险

### 示例2：产品设计（功能优先级排序）

用户提交一份"产品功能优先级TOP10"，询问是否合理。

按本框架审视：
- **事实核查**：各功能的用户量/频次数据是否准确？来源是否可靠？
- **Scope校验**：是否只考虑了新功能，漏了存量功能优化？是否区分了B端/C端？
- **遗漏补全**：是否有竞品已上线但本榜单忽略的功能？是否有用户反馈高频但未入榜的需求？
- **排序争议**：某"高技术难度"功能是否因开发成本被低估？某"低频但高价值"功能是否被错放低档？
- **方法论补强**：是否区分"用户价值"与"商业价值"？是否考虑技术可行性权重？ROI测算是否透明？

## 注意事项

1. **先校准日期**：涉及"已发生/未发生"判断时，必须先调用 `get-current-date` 技能获取真实日期，禁止用环境注入日期。
2. **事实核查优先**：5个维度中，事实核查最硬--事实错误必须先改，否则后续讨论无意义。
3. **避免为批判而批判**：若分析确实优秀，应明确说"完全同意"，只提边际改进建议，不强行找茬。
4. **跨领域适用**：维度名称（如"管线/靶点"）可替换为对应领域术语（"功能/需求""标的/策略"），框架逻辑不变。
5. **输出克制**：只针对有问题的部分展开，无误部分一笔带过，避免冗长。
